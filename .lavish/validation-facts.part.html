Facts about no-mistakes

Checked on this host on 2026-10-05 against the installed copy and its official docs. These are observations, not qualification.

  • What it is. A separate product by Kun Chen, under the MIT licence (kunchenguid/no-mistakes), not a Matt Pocock skill. The installed copy is v1.84.0, the latest stable release (26 September). There have been 176 releases since v1.0.0 in April, with daily prereleases (v1.87.1 on 4 October).
  • Setup writes outside the repository. no-mistakes init adds a no-mistakes remote to the repository and creates a bare gate repository under ~/.no-mistakes/repos. It installs its skill into ~/.claude/skills and ~/.agents/skills and starts its own per-user daemon as a systemd or launchd service.
  • A fixed pipeline in its own checkouts. A push to the no-mistakes remote starts a run in a disposable checkout under ~/.no-mistakes/worktrees. The steps run in a fixed order: intent → rebase → review → test → document → lint → push → PR → CI. A step can be skipped for one run but never removed. A second push to the same branch cancels the active run.
  • Its own agents. Each step runs one-shot claude or codex subprocesses, taking the first one found on PATH (here, your personal copies in ~/.nix-profile/bin) unless a path override is configured. They run outside any terminal AsmAI owns.
  • It rewrites and moves the branch. The rebase step rebases the branch onto the fresh base, and fix rounds commit to the branch. The push is guarded so it never discards commits already on the target. It pushes, then opens or updates the PR.
  • It keeps working after checks pass. It watches the PR until it is merged or closed. On a merge conflict it rebases, validates again and re-pushes, and it can auto-fix CI failures.
  • Human gates. Review findings are never auto-fixed by default. An ask-user finding must go to the human word for word, unless the human has consented to --yes. checks-passed means ready for a human to review and merge, never merged.
