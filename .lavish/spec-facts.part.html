Facts for this ticket

Checked on 2026-10-06 in this repository, the installed skills and GitHub. These are facts, not decisions.

  • Size of what the specification consolidates: the decisions in the 15 resolved tickets come to about 110,000 characters before their evidence sections. The glossary and ADRs 0001 to 0008 add about 24,000 more.
  • GitHub's limit: an issue body holds at most 65,536 characters, so v1's specification cannot fit in one issue.
  • to-spec (on Planning workers' list) writes one spec in a fixed form (problem, solution, a long list of user stories, implementation decisions, testing decisions, out of scope, notes) and publishes it as one issue in the tracker. to-tickets works from an issue or a file path and turns it into vertical-slice tickets with native blocking edges.
  • This repository today holds no code: GLOSSARY.md, ADRs 0001 to 0008, two research notes, the Lavish boards and the historical .scratch snapshot. ADR 0009 and the Release, Store and Upgrade glossary terms from Choose license, release packaging and upgrade migration are still waiting to be archived.
  • Renaming a GitHub repository redirects the old web, issue and git URLs to the new name, unless a new repository later takes the old name. A Go module path is written into every import, so changing it after code exists means rewriting every import path.
  • Configuration and agent instructions are the map's only remaining fog. Every setting's meaning and default is already decided; their field names, and the wording of the agent instructions, are not.
