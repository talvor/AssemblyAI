R3-Q1

Who runs the Lavish review server on a host?

Lavish is required for every review and grilling/Wayfinder question, including those raised while you are away. Options: (A) The AsmAI daemon starts and supervises the factory's Lavish server, like any other factory component, and Coordination gives you the URL and the SSH forwarding command. (B) Agents start Lavish on demand through `lavish-axi`, as today, and the daemon does not manage it.

Recommended: A. The daemon owns Lavish's lifecycle, so pending decisions survive agent restarts and a reboot, and their review pages come back with the factory. Lavish binds only to localhost and is reached remotely through SSH forwarding.

R3-CONFIRM

Confirm the hosting and lifecycle resolution

Factory: one per OS user per host, installed without root; local and remote are independent factories with no shared state. Platforms: Linux and macOS, each certified separately against the same qualification bar, so Linux may launch first and an uncertified platform refuses to start agents. Supervision: a per-user AsmAI daemon owns every provider PTY, the input fence, and hook intake, and tmux is not required. You start it with `asmai start`; `asmai service install` optionally adds a systemd user unit (with linger) or a launchd LaunchAgent so it starts after a reboot. Remote access: SSH only, attach on the host, Lavish through port forwarding, and no network listener. Leadership: at most one leader per role at any instant, enforced by fencing that rejects stale processes. A leaderless gap is tolerated and that role's requests wait durably; there are no standby leaders. Recovery: survives terminal or SSH disconnect, agent crash, daemon crash, and host reboot; host loss and migration are out of v1. Leaders are restarted automatically on the same provider, with bounded retries before the role pauses and you are told. A dead worker's assignment needs reconciliation by its owning leader, never a blind retry. Every start goes through the same recovery path. Stop: drain new dispatches, let turns reach a boundary up to a timeout, then interrupt; `--now` skips the wait. Pending decisions, grants, and queued requests persist. Takeover: attaching observes; taking input is explicit, waits for the turn boundary by default with interrupt as an option, and records and clears any unsent automated draft first. Detaching without releasing leaves automation paused. Modals: an allow-list of qualified modals that starts empty and never permits answers that change provider, model, authentication, or permissions; everything else pauses and escalates. Upgrades: stop, upgrade, start; versions are validated at start, and no hot upgrade is supported. Deferred: storage, fencing mechanics, and reconciliation records go to the work-state ticket; notifications while you are away go to the operating limits and visibility ticket; packaging goes to CLI setup; adverse-case qualification goes to acceptance.
