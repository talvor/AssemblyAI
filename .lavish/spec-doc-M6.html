M6 Recovery

M6 makes the factory survive what goes wrong on a host: full reconciliation, generations and fencing, termination of orphaned agents, agent and daemon crashes, a host reboot with the service installed, asmai stop draining, terminal disconnects, and a crash during a push or between the push and the pull request (AssemblyAI#27).

What it adds

  1. Full reconciliation by the owning leader, against the real repository and GitHub, with silence and conflicting observations making a dispatch unknown (AssemblyAI#27, 02).
  2. Generations and fencing, so a superseded session can never write (AssemblyAI#27, 02).
  3. Orphan termination at every start (AssemblyAI#27, 02).
  4. Crash recovery: an agent crash, a daemon crash, and a host reboot with the service installed, as a systemd user unit or a launchd LaunchAgent (AssemblyAI#27, 02).
  5. asmai stop draining, and --now (AssemblyAI#27, 02, 07).
  6. Terminal disconnect leaving agents running (AssemblyAI#27, 02, 03).
  7. Delivery crashes: a crash during a push, or between the push and the pull request (AssemblyAI#27, 06).
  8. Automatic retries of assignments declared side-effect-free, in place of reconciliation (02, 07).

Builds on

M5 Concurrency and limits: concurrent jobs, holds and leaders on demand, which recovery must restore correctly.

Demo path

S8, local continuity, on the fixture repository (AssemblyAI#27, 11): during a feature job, the user leaves and comes back to a catch-up; the daemon is killed; and the host reboots with the service installed. Each affected assignment either continues or has a recorded reconciliation, no effect appears twice in the journal or on GitHub, and the job still ends as a tested pull request.
