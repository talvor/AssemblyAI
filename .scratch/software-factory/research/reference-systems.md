Research date: 2026-10-03. Read-only source inspection; no live fleet or failure-recovery test was run. This is an ideas pool, not a dependency selection.

## Firstmate

- **Coordination contract:** one user-facing supervisor delegates project work, with workers reporting through it. Task workers receive isolated worktrees; optional persistent secondmates receive isolated operational homes. The supervisor's project-write restriction is predominantly an instruction contract, with named exceptions, not evidence of an OS-enforced security boundary. [Supervisor contract](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/AGENTS.md), [README](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/README.md).
- **Launch binds intent to delivery:** `fm-spawn.sh` requires task delivery mode and merge-autonomy setting for shipping work and rejects a mismatch against the written brief. Scouts and secondmates have different launch forms. This is a useful example of checking contract consistency in code instead of relying entirely on prompts. [Spawn implementation](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/bin/fm-spawn.sh).
- **Messages persist before notification:** task inbox files are sequence-numbered, written with atomic rename, and moved into `handled/` to acknowledge them. A terminal receives a short doorbell pointing to the inbox. A bounded retry ladder detects missing acknowledgement and escalates. Duplicate notifications therefore need not duplicate the durable message. This is not proof of exactly-once external side effects if a worker crashes between doing work and acknowledging it. [Inbox owner](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/bin/fm-task-inbox-lib.sh).
- **Recovery distinguishes events from truth:** status files contain append-only wake events, not current state. `fm-crew-state.sh` reconciles task metadata, runtime observations, and matching delivery-pipeline evidence; it does not treat the last status line as authoritative. Durable preferences, backlog, briefs, and runtime records survive chat context loss. [State reconciliation](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/bin/fm-crew-state.sh), [supervisor recovery contract](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/AGENTS.md).
- **Unattended supervision has machinery:** a durable wake queue, watcher, and harness-specific continuation mechanisms support supervision. Lifecycle commands distinguish interrupt delivery from confirmed cancellation and preserve work during relaunch. Availability and guarantees depend on the harness/backend combination. [Wake library](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/bin/fm-wake-lib.sh), [control-plane contract](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/docs/agent-control.md).

## OpenRig (mvschwarz)

- **Runtime architecture:** a local daemon coordinates harness sessions in tmux; CLI, TUI, and MCP use its local HTTP API. SQLite retains runtime state. Role/spec/context projection equips persistent seats; this is broader than a mandatory single-supervisor hierarchy. The architecture document warns that its older counts can be stale. [Architecture](https://github.com/mvschwarz/openrig/blob/887063afdd585b9264b33fbcc7b388b00e075fa9/ARCHITECTURE.md).
- **Owned work is separate from chat:** the getting-started pair has an owner and independent checker. The owner creates and claims durable work and routes review without human relaying. Scope artifacts retain what is being built; optional workflow instances retain who acts next. A delivered message alone is not evidence of reviewed work. [Getting started](https://github.com/mvschwarz/openrig/blob/887063afdd585b9264b33fbcc7b388b00e075fa9/docs/reference/getting-started.md).
- **Concrete state schema:** `queue_items` stores source/destination, state, handoff ancestry, blocking, closure fields, heartbeat, nudge result, and resolution. Markdown mirrors are described as exports, while SQLite is canonical for runtime work. [Initial queue migration](https://github.com/mvschwarz/openrig/blob/887063afdd585b9264b33fbcc7b388b00e075fa9/packages/daemon/src/db/migrations/024_queue_items.ts).
- **Wake durability:** `queue-wake-ladder.ts` separates one durable obligation from repeated notification attempts. Transition records reconstruct retry/escalation position after restart. Failed handoff notifications advance through bounded retries to orchestrator/operator escalation; unconfirmed delivery follows a different path to avoid resending uncertain content. These are implementation mechanisms, not an end-to-end reliability guarantee. [Wake ladder](https://github.com/mvschwarz/openrig/blob/887063afdd585b9264b33fbcc7b388b00e075fa9/packages/daemon/src/domain/queue-wake-ladder.ts).
- **Transport has an adapter maintenance burden:** session transport combines runtime hooks, process identity, pane observations, and prompt-detection patterns. Its code explicitly handles stale observations and unavailable transport. Keeping native CLI UI changes compatible is a material ongoing cost. [Transport](https://github.com/mvschwarz/openrig/blob/887063afdd585b9264b33fbcc7b388b00e075fa9/packages/daemon/src/domain/session-transport.ts).

## Reusable ideas and constraints

The shared lesson is architectural: keep durable work, ownership, notification, live process state, and completion evidence distinct. An agent's conversational memory should not be the only record of an obligation. A reconnect or restart must reconcile existing work before spawning replacements. These are deductions from the mechanisms above, not decisions for this factory.

Firstmate supplies a directory of instructions, skills, state conventions, and shell tools rather than a packaged product CLI. OpenRig already supplies a daemon-backed CLI and a much wider coordination model. Reusing either entails accepting or adapting its lifecycle and harness dependencies; neither inspection established a small stable library API suitable for embedding. [Firstmate README](https://github.com/kunchenguid/firstmate/blob/c5f48e4cad279e6acaf14208522c44e28fac6835/README.md), [OpenRig architecture](https://github.com/mvschwarz/openrig/blob/887063afdd585b9264b33fbcc7b388b00e075fa9/ARCHITECTURE.md).
