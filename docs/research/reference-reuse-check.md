## Verified findings

- **Firstmate is a distro, not an embeddable runtime package.** Its directory contains supervisor instructions, scripts, skills and state conventions. It supports a supervisor with task workers and optional persistent secondmates, including separate homes on SSH hosts. Claude Code and Codex are documented primary harnesses, with different supervision mechanisms. Its internal skills explicitly assume a Firstmate home; the public standalone skill is a separate surface. [Pinned README](https://github.com/kunchenguid/firstmate/blob/1f3e769616fdf9f31f85f4c3e6a9f71606634238/README.md).
- **Firstmate's root license is MIT.** The checked local and upstream license texts agree. This is a root-license identification, not an audit of every bundled asset. [License](https://github.com/kunchenguid/firstmate/blob/1f3e769616fdf9f31f85f4c3e6a9f71606634238/LICENSE).
- **OpenRig offers actual integration surfaces.** The published `@openrig/cli` bundles its daemon, UI and TUI. The daemon package is private; its exports primarily share code within the workspace rather than establishing an independently published runtime library. CLI, TUI and MCP use a local HTTP daemon over SQLite and terminal sessions. The architecture document acknowledges its own historical counts. [CLI package](https://github.com/mvschwarz/openrig/blob/c0ca7d875922bb2439718c2dcfabc1ac0d134b03/packages/cli/package.json), [daemon package](https://github.com/mvschwarz/openrig/blob/c0ca7d875922bb2439718c2dcfabc1ac0d134b03/packages/daemon/package.json), [architecture](https://github.com/mvschwarz/openrig/blob/c0ca7d875922bb2439718c2dcfabc1ac0d134b03/ARCHITECTURE.md).
- **OpenRig allows custom role/topology configuration.** RigSpecs describe pods, members, runtimes, working directories and delegation/escalation edges. AgentSpecs select role guidance, skills, hooks and lifecycle settings. These are documented extension points; they do not prove that AsmAI's precise worker ownership, per-job isolation and authority rules are already enforced. [RigSpec](https://github.com/mvschwarz/openrig/blob/c0ca7d875922bb2439718c2dcfabc1ac0d134b03/docs/reference/rig-spec.md), [AgentSpec](https://github.com/mvschwarz/openrig/blob/c0ca7d875922bb2439718c2dcfabc1ac0d134b03/docs/reference/agent-spec.md).
- **OpenRig explicitly documents own-account interactive Claude/Codex operation.** Its getting-started path checks the chosen native CLI login and supports mixed teams. Installation requires Node and tmux; startup can modify provider hooks and trust settings. Repository guidance can run ahead of the published package. This is evidence of product fit, not a provider entitlement determination or verified AsmAI session-recovery guarantee. [README](https://github.com/mvschwarz/openrig/blob/c0ca7d875922bb2439718c2dcfabc1ac0d134b03/README.md).
- **OpenRig's root license is Apache-2.0.** No dependency-wide license audit was performed. [License](https://github.com/mvschwarz/openrig/blob/c0ca7d875922bb2439718c2dcfabc1ac0d134b03/LICENSE).

## Engineering assessment (inferences, not established capabilities)

| Approach | Plausible fit | Maintenance and unresolved cost |
|---|---|---|
| Independent AsmAI implementation, references as examples | Full control over five factory-wide leaders, assignment-scoped workers, CLI shape and human decision gates | Own every runtime adapter, durable-state transition, recovery mechanism and regression test. Inspiration does not transfer reliability. |
| Configure or wrap OpenRig through its CLI/HTTP/MCP and custom specs | Strongest existing packaged foundation; could express leader seats and role guidance without immediately forking | Accept its daemon, storage, installation effects and lifecycle model. Prove per-job isolation, dynamic assignment workers, remote operation and exact authority semantics; pin and test upstream updates. Avoid a second competing source of work truth. |
| Extend/fork Firstmate | Supervisor/secondmate hierarchy and interactive harnesses are close to the concept; local/remote homes already exist | Translate secondmates into factory-wide role leaders; adapt direct-report and state conventions, packaging and policy. A small wrapper cannot be assumed to hide this coupling. Fork requires carrying upstream merges. |
| Fork OpenRig | Maximum access to an existing coordination implementation | Broad codebase and migrations become part of AsmAI maintenance; policy/runtime changes may conflict with upstream. Only justified by concrete gaps that configuration cannot address. |
| Copy selected implementation components | May save effort for a well-bounded primitive | Neither inspected project established a small standalone supported library for the entire runtime. Extraction requires dependency/contract review, attribution, tests and an explicit update policy; copied code is maintained locally. |

Recommendation for the conversation: present independent implementation and an OpenRig-backed configuration/wrapper as genuinely distinct plausible choices. If the user prefers reuse, require a bounded feasibility check before declaring the fit proven; if the user prefers independence, record that they accept the runtime/recovery maintenance cost. Firstmate remains a valuable mechanism reference and possible fork base, but its distro shape makes it a less direct packaged foundation. The already-open interactive CLI feasibility investigation remains necessary whichever approach wins.

No choice here inherently imports the reference system's permission policy or resolves hosting, state contracts, worker lifecycle, skill selection or validation ownership. Those remain explicit AsmAI decisions.
