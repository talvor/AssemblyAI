# Domain docs

## Read before exploring

This repo uses a single-context layout.

Read the root GLOSSARY.md and any ADRs in docs/adr/ relevant
to the area being explored.

If these files are absent, proceed silently. Domain modeling
creates them when terms or decisions are resolved.

## Use domain vocabulary

Use glossary terms in issue titles, proposals, hypotheses,
and tests. Respect explicitly avoided synonyms.

If a needed concept is missing, reconsider the terminology
or note the gap for domain modeling.

## Surface decision conflicts

Explicitly flag proposals that contradict an existing ADR,
including the decision reference and reason to revisit it.
